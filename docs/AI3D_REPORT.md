# AI 3D 模型生成 · 开发报告（任务书 v1.66，实际版本号 v1.67）

> 版本说明：v1.66 已被「MIT 许可证与 Openverse 授权收紧」占用并发布，按 AGENTS.md「每个版本保留独立版本号」，本任务以 **v1.67** 发布。

## 结论

- **已实现（P0）：** 单张图片 → 真实深度网格（闭合的「深度立体模型」）→ RealityKit 预览 → 保存、重新加载、删除、导出。视频 → 有界抽帧、模糊/重复检测、视角覆盖评估、人物视频识别、设备能力检测。任务可取消，有温度、内存保护，错误可恢复。全部本地运行，不联网、不上传。
- **条件支持（P1）：** 支持机型上的 RealityKit Object Capture 多视角重建、整体材质 / 贴图换装与皮肤预设、OBJ / USDZ 导出、按设备自动选择网格精度。
- **未实现（P2，实验性）：** 单图 360° 重建、自动骨骼、蒙皮、动画适配、服装分离、自由换装。代码中这些能力固定标记为「实验性，未实现」，不会显示为完成。
- **没有真机测试证据：** 开发环境是 Linux 云端容器加 GitHub Actions 的 macOS 编译机，没有 iPhone。第十二节要求的 12 项真机测试都**尚未执行**，下表如实标注。

## 图片 → 3D（模块 A）

1. 用 ImageIO 读取 JPG、PNG、HEIC，按方向校正，缩放到贴图尺寸。
2. 深度来源，按顺序尝试：
   - 照片自带的相机深度或视差（人像模式、双摄、LiDAR）。这一路不需要 AI，iOS 16 也能用。
   - 否则用 **Depth Anything V2 Small**（Apple Core ML F16，Apache-2.0，约 49 MB，需要 iOS 17）。模型首次使用时编译并缓存，每次生成单独加载，用完即释放。
   - 两者都不可用时明确报错，不生成任何结果。
3. 主体识别依次尝试：
   - Vision 前景实例分割（iOS 17）；
   - 人像分割（iOS 15）；
   - 都失败时，按深度直方图的 Otsu 阈值取近处部分作为前景，并在模型说明里记录这一点。
   - 主体覆盖低于 2% 时报「没有识别到主体」。
4. `DepthMeshBuilder` 生成网格：
   - 网格每个顶点的 z 值取自深度，按 2–98 分位数归一，并做平滑。
   - 正面三角形的轮廓边生成侧壁，再加平板背面，得到闭合模型。测试验证了每条边恰好被两个三角形共享，即水密。
5. 原图作为 UV 贴图。模型居中并归一到 1 个单位。
6. 结果标记为「深度立体模型（正面为真实深度，背面为封闭平板，非完整 360°）」。

## 视频 → 3D（模块 B）

- 用 AVFoundation 抽帧：最多 90 帧、最长 1920 px、只分析前 3 分钟。帧以 JPEG 存入临时目录，内存只保留统计数据，即有界缓存。
- 每帧计算以下数据：
  - 拉普拉斯方差，用于判断模糊；
  - 差值哈希，用于判断重复；
  - Vision 平移配准，估计镜头移动；
  - 人体检测。
- 评估结果分四类：
  - 「可多视角重建」：至少 20 张有效帧，且累计移动至少 1.5 个画面宽度；
  - 「视角不足」：提示重拍；
  - 「固定机位人物视频」；
  - 「有效画面太少」。
- 只有「可多视角重建」且 `PhotogrammetrySession.isSupported` 时，才运行 RealityKit Object Capture。生成的 USDZ 必须能被 RealityKit 实际加载才会保存。
- 其他情况提供「用最清晰一帧做深度立体模型」。

## 资源目录（模块 G）

`Application Support/Generated3D/` 下有这些子目录：
- 任务书要求的：`Models/`、`Textures/`、`Skeletons/`、`Animations/`、`Thumbnails/`、`Presets/`、`Manifests/`；
- 另外两个：`Engines/`（编译好的 Core ML 模型）、`Exports/`。

每个模型有一份 `Manifest.json`，记录以下内容：
- 唯一 ID 和来源文件的 SHA-256；
- 生成引擎及其版本、深度来源；
- 几何类型、精度、顶点数和三角面数、贴图尺寸；
- USDZ 是否导出并通过加载验证；
- 人形检测结果，以及骨骼、动画、换装各自的能力状态；
- 皮肤预设和说明。

同一图片、同一精度再次生成时，直接复用已有结果，不会重复占用空间。删除模型时，会一并删除它的所有文件。

## 已知限制

- **单张图片只能恢复正面。** 背面是平板，侧面是轮廓拉伸出来的壁，不是完整 360° 模型。
- **深度是相对值。** 单目深度没有真实比例，立体程度按画面高度的 35% 设定。
- **USDZ 导出用的是 Model I/O。** 系统支持时导出，并实际加载验证，失败就不保留。贴图是否完整嵌入 USDZ 需要真机确认。内部格式（`.m3dg` 加 JPEG 贴图）和 OBJ 导出不受这个限制。
- **多视角重建条件较严。** 依赖 Object Capture 支持的机型（iOS 17+）。视频帧没有深度和重力数据，重建质量可能低于用相机直接拍摄。
- **可动画角色。** 生成的模型用作 3D 世界角色时是静态模型，没有骨骼动画。
- **网格精度与内存。** 按设备内存和温度自动选择，高温时会暂停或拒绝生成。不承诺所有 iPhone 都能在固定时间内完成。
- **最低系统版本。** 应用最低版本仍是 iOS 16。AI 深度需要 iOS 17，3D 预览界面需要 iOS 18（与 3D 世界一致）。

# P2 研发记录（v1.68，实验性）

> 原则不变：P2 在真机验证前不算完成。下面写「已实现」的，代码和自动化检查都已到位，但**没有任何真机验证**。

## 已实现（实验性）

### 自动骨骼、蒙皮与动作

- **适用范围：** 只做深度立体模型，并且原图里要有完整的人形姿态：Vision 能检测到脖子、双肩、双髋，置信度 ≥ 0.3。
- **骨骼：** 共 10 根，包括躯干、头、左右上臂和前臂、左右大腿和小腿。
  - 关节位置来自 Vision 在模型原图上识别的 2D 姿态。
  - 每个关节的 x、y 由「图片坐标 → 模型坐标」的线性映射算出：深度模型的每个顶点都保留了图片坐标，用最小二乘拟合得到这个映射。
  - 深度取该处正面与背面的中点。
  - 缺少手腕、脚踝时，省略对应的前臂或小腿骨骼。
- **蒙皮：**
  - 每根骨骼只从「画面平面上靠近自身中心线」的顶点出发，沿网格表面计算距离（测地距离），权重按距离的 4 次方反比计算；
  - 再沿网格平滑 6 次，最后每个顶点保留权重最大的 2 根骨骼。
  - 改用测地距离的原因：直线距离会让贴着身体的手臂拉动躯干，测试人形的最大接缝拉伸达到 16 倍。
- **动作：** 待机、行走、奔跑、挥手 4 个程序化动作，以正弦关键帧存储，保存在 `Animations/`。
- **自动检查（`RigValidation`）：** 每个动作取 8 个时刻实际变形网格，检查以下三项：
  - 顶点坐标都是有限值；
  - 移动幅度：待机 ≥ 0.4% 身高，其他动作 ≥ 2% 身高；
  - 接缝拉伸：拉长超过 4 倍的边，占比不超过 2.5%。
  - 只有通过检查的骨骼才会保存，模型标记为「实验性：已通过本机自动检查」（`experimentalVerified`），**从不标记为正式完成（`ready`）**。没通过时保持静态模型，并给出原因。
- **播放：** 在 CPU 上做线性混合蒙皮，按身体区域拆成 4 个 RealityKit `LowLevelMesh`，每秒最多更新 30 次。
- **Linux 测试结果（合成站立人形）：**
  - 手跟随前臂，脚跟随小腿，胸口跟随躯干；
  - 静止姿势下网格不变；
  - 挥手能抬起右手，双脚不动；行走时腿前后摆动；
  - 接缝拉伸：行走 0.06%、奔跑 0.12%、挥手 0%；
  - 缺少髋部、或脖子置信度低时不生成骨骼。
  - 相关检查在 P31 中，测试总计 4224 项全部通过。

### 身体分区换色

骨骼绑定后，可以给头部、躯干、手臂、腿部分别设颜色，并保存进皮肤预设。界面写明「身体分区，不是独立服装」。

### 背面「镜像推测」

生成时可以选择让背面按正面深度的 70% 鼓起，转动模型时更有体积感。界面和模型说明都写明「推测，不是 AI 重建」。

# v1.69：质量改进与放入世界

## 质量（针对用户录屏：侧面拉伸条纹、侧看是厚块、背面印着正脸）

- **形体推测（默认）：**
  - 在轮廓内求解 ∇²h = −2（轮廓上 h = 0），取 z = √h。任意宽度的条带都会得到半圆截面，所以细的部位薄而圆，宽的部位厚而圆。
  - AI 深度只叠加 ±25% 的正面细节，并在靠近轮廓处逐渐减弱为零。
  - 背面厚度为正面的 85%。
  - 测试结果：21 格宽条带中心高 11 格，符合半圆；细臂厚度不到身体的一半。
- **去掉侧墙：**
  - 正反面在轮廓处 z = 0，直接闭合，不再有侧墙，因而不会出现拉伸的贴图条纹。
  - 测试结果：按位置统计，没有任何一条边只出现一次。
- **背面贴图：**
  - 贴图改为左右拼接 [原图 | 背面颜色]。
  - 背面颜色由原图模糊到约 12 像素后放大，再以 60% 混合主体的平均色得到，不含五官细节。
  - 骨骼绑定会从左半张图识别姿态，并把 u 坐标换算回贴图坐标。
- **轮廓：**
  - 对轮廓上的每个顶点，沿法线在原分辨率遮罩上二分查找 0.5 的交界线。
  - 测试结果：轮廓起伏的标准差降低 40% 以上。
- **深度：**
  - 用以原图为参考的联合双边上采样，把深度图放大到最长边 512 像素，让深度边缘对齐图片边缘。
  - 测试结果：深度台阶落在图片的边缘处，比普通缩放更清楚。
- **网格密度：**
  - 网格由 96 / 144 / 208 提高到 128 / 192 / 288。

## 放入世界

- 新增角色外观类型 `generated`，直接读取生成的网格，不再需要 USDZ。
- **动作：**
  - 绑定了骨骼的模型，按世界里的动作播放对应片段：行走 → 行走；奔跑、跳跃、闪避 → 奔跑；攻击、技能 → 挥手；其余 → 待机。
  - 同一模型、同一动作的角色共用一个形变网格，蒙皮计算每秒更新 20 次。
- **单独放置：** 「生物」工具新增「外观」选项，可以只给新放置的那一个生物指定外观。

## 未验证

真机上的生成效果、动画角色较多时的帧率，以及拼接贴图在 RealityKit 中的显示，都还没有在真机上验证。

## v1.72：可选的 Claude 动作设计（联网例外）

- 生成 3D 模型仍完全本机离线。唯一的联网功能是用户主动开启的「用 Claude 设计动作」。
- 需要用户自己的 Anthropic API Key，保存在本机钥匙串中。每次发送前都会弹窗确认要发送的内容：只有文字描述和 10 根骨骼的关节坐标，不包含图片、贴图或网格。
- 请求：Messages API，默认 `claude-opus-5-5`。用结构化输出（`output_config.format` json_schema）限定动作格式，并开启服务端 `fallbacks: "default"`（beta `server-side-fallback-2026-07-01`）：主模型拒绝时，由 Anthropic 推荐的备用模型重试。
- 回答处理：先检查 `stop_reason`（`refusal` / `max_tokens`），再把动作夹到安全范围（角度 ±90°，躯干和头部 ±45°；周期 0.4–4 s；整数循环数）。动作必须通过与标准动作相同的 `RigValidation` 变形检查才会保存；AI 动作最多保留 8 个，可长按删除。
- 未完成：Claude 不修改骨骼结构或蒙皮；没有用真实 API 联调，也没有真机验证。
