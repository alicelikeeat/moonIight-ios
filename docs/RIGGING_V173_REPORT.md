# Moonlight v1.73 自动骨骼绑定 — 实现说明与测试报告

基线：v1.72（分支 `claude/moonlight-ios-v160-3d`）。本报告只记录实际完成和实际测得的内容。

## 1. 仓库审计（P0）

| 项目 | v1.72 实际情况 |
| --- | --- |
| 部署目标 / 语言 | iOS 16.0，Swift 6（严格并发）；3D 生成与 RealityKit 功能要求 iOS 18 |
| 3D 管线 | 单张图片或视频 → 深度立体模型（自有 `.m3dg` 网格 + 贴图）；支持的设备上可用 Object Capture 多视角重建（USDZ）。**目前没有“2～6 张图片生成模型”的流程**，v1.73 按任务书要求以“已生成的网格”为输入 |
| 已有骨骼 | v1.68 的 10 骨骼绑定：关节来自原图的 2D 人体姿态（Vision），每顶点 2 个权重，正弦动作，自动变形检查 |
| RealityKit 用法 | `RealityView`、`LowLevelMesh`；骨骼动画由 CPU 蒙皮写入 LowLevelMesh，没有用 RealityKit 的骨骼资源 |
| 持久化 | `Application Support/Generated3D/` 下按类型分文件夹，模型清单为 JSON |
| 测试 | 纯 Swift 领域代码在 Linux 上编译测试（`Tests/RPG/main.swift`），iOS 代码在 GitHub Actions 的 Xcode 上编译 |

**兼容性风险**
- RealityKit 只负责骨骼姿态，不计算蒙皮权重，所以需要自己的转换层。
- 旧模型清单的枚举新增了值（`imported`、`none`）。新文件在旧版应用中读取会失败，旧版会跳过它，不会误读。
- v1.72 的骨骼文件保持原样。

## 2. 架构

```
Features/Rigging/
  Domain/RiggedCharacter.swift        骨骼数据层（与 SwiftUI / RealityKit 无关）
  Engine/MeshAnalyzer.swift           网格诊断、坐标统一、清理、简化
  Engine/JointEstimator.swift         从 3D 网格横截面识别人形关节
  Engine/SkeletonBuilder.swift        27 关节骨架、关节限制、挂点、姿态求值
  Engine/SkinWeightSolver.swift       CPU 自动蒙皮（测地距离 + 扩散）与 LBS 变形
  Engine/MotionValidator.swift        动作库与 8 项自动动作测试
  Engine/GLBCodec.swift               GLB 读写
  Services/RiggingPipeline.swift      本地流水线、自动修正、本地/云端决策
  Services/CloudRiggingProtocol.swift 云端任务协议与结果校验
  Services/RiggingAssetStore.swift    保存、回滚、版本检查、检查点
  Services/RiggingCoordinator.swift   任务调度（取消、重试、过热/内存/后台暂停）
  UI/AutoRigView.swift                四页工作台
  UI/RigPreviewScene.swift            RealityKit 预览适配层
```

建议目录里的 `RiggingUnitTests` 和 `RiggingIntegrationTests` 没有单独建文件，测试并入现有的 Linux 测试程序（P39 段）。这样它们会和其余 4,300 项检查一起在 CI 中运行。

## 3. 完成情况（按任务书模块）

| 模块 | 状态 | 说明 |
| --- | --- | --- |
| M01 工作台 | 已实现，未经真机验证 | 模型详情页「自动骨骼工作台」入口。四页共用一个预览和一个协调器，切页保留进度。默认只有「自动绑定」主按钮，其他在「高级设置」。任务有进度、取消和重试。长按关节显示菜单。关节编辑全部用按钮和滑块，不占用预览的拖动旋转手势 |
| M02 预处理 | 部分完成 | **已做**：坐标统一（脚底 y=0、高 1、居中）；检查退化三角形、重复面、非流形边、开放边、法线、连通块、对称度、包围盒；清理副本；超过 150,000 面时生成简化副本。**未做**：头发、衣服、武器与身体连在一起时无法语义分离。目前只把小的独立网格块当作刚体配饰 |
| M02 关节识别 | 第一级完成 | 在 3D 网格上用水平和竖直平面截面识别双腿、手臂（下垂 / T / A 姿势）、颈部，关节放在截面中心，所以深度方向也在身体内部。没有使用 2D 图片姿态 |
| M03 骨骼生成 | 已完成 | 27 个关节，每个关节含 jointID、parentID、restTransform、inverseBindMatrix、jointLimit、semanticTag、confidence。校验无环、根骨骼唯一、矩阵有效且与逆绑定一致、左右结构合理、上下顺序正确。区分 T-Pose / A-Pose / 下垂 / 非标准。**未做**：非标准姿势下先调整绑定姿态再蒙皮 |
| M04 自动蒙皮 | 已完成（CPU） | LBS，每顶点最多 4 个权重，非负且归一化。用网格测地距离和截面可见性确定归属，扩散平滑，并对肩、肘、髋、膝做额外处理。小配件刚性绑定。修正前保留撤销记录。**未做**：Metal 加速、双四元数蒙皮 |
| M05 云端 | 客户端已实现，**无服务端** | 5 个接口的客户端已实现：用户确认后才上传，HTTPS，令牌存钥匙串，有超时，可删除云端任务。结果先做版本、顶点数、骨骼和权重校验，再跑本地动作测试。**应用没有内置任何服务，UniRig 未部署或测试**，接口约定见 `docs/RIGGING_CLOUD_API.md` |
| M06 RealityKit 预览 | 已实现，未经真机验证 | CPU 蒙皮写入 LowLevelMesh。可显示或隐藏骨骼（透视），选中单个关节旋转，显示关节坐标轴，恢复绑定姿态，连续播放多个动作。保存后重新加载用的是同一份文件。**未做**：真机验证；也没有改用 RealityKit 骨骼资源 |
| M07 动作测试 | 已完成 | 8 项：绑定姿态、抬手、弯肘、下蹲、行走、跳跃、转身、挥剑。结果分通过 / 警告 / 失败。检查网格撕裂与挤压、矩阵异常、关节越界、手臂穿入躯干（近似）、脚穿地面、跳跃离地、双腿交替、武器挂点轨迹。失败时自动修正，并记录修正前后数据 |
| 世界接入 | 已实现 | 保存了 v1.73 骨骼的模型，放进世界后用它做动作（待机、行走、奔跑、跳跃、挥剑、挥手）。没有新骨骼时仍使用 v1.72 的绑定 |
| GLB 导入 | 已实现 | 读取 glTF 2.0 二进制网格、节点变换和第一张底色贴图。文件中已有的骨骼和动画不读取 |

## 7. 给技能编辑器的数据接口

`RiggedCharacter`（`Rigs/<模型ID>.rig.json`，格式版本 1）包含：
- `skeleton.joints[]`：每个关节有 jointID、parentID、restTransform、inverseBindMatrix、jointLimit、semanticTag、confidence；
- 权重文件 `Rigs/<模型ID>.skin`（每顶点 4 组关节索引和权重）；
- `clips`：动作库；
- `sockets`：右手武器、左手盾牌、背部、左右脚底、头部；
- `diagnostics`：测试结果与修正记录；
- `metadata`：引擎、来源、姿势、时间；
- `optimizedMeshFile`：高面数模型的简化副本。

动作求值用 `MotionClip.pose(skeleton, at:, height:)`，变形用 `SkinWeightSolver.deform`。两者都不依赖界面。

## 8. 限制

- 本环境不能运行 Xcode 和 iPhone，iOS 代码只在 CI 编译。**没有任何真机测试结果**。
- 关节识别面向站立的标准人形。四足、机械、坐姿等不在本版范围内，会提示使用云端。
- 衣服或头发与身体融为一体时，只能通过权重平滑减轻拉伸，无法分层。
