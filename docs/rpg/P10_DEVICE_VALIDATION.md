# 真机性能验证（尚未执行）

目前只有 GitHub macOS/iOS Simulator 构建与自动化环境，未连接真实 iPhone。此文是可执行验证步骤，不是性能通过报告。

## 采样步骤

1. 记录 iPhone 型号、iOS 版本、电池状态、低电量开关、环境温度、构建 SHA 和签名。
2. 以固定 Seed 连续探索 10 分钟，往返跨区块；放置/破坏/撤销，并在神殿切换俯视和侧视至少 30 次。
3. 分别使用静态媒体、1 路及 2 路视频，重复使用同一视频绑定大量方块，验证实际解码数量而非绑定数量。
4. 完成俯视、侧视遭遇和 Boss 两阶段，分别记录帧间隔 p50/p95/p99、>50ms 卡顿、CPU、内存 footprint/峰值与热状态。
5. 打开/关闭媒体编辑器和剧情演出 30 次，切后台 30 秒后恢复；检查声音默认静音、解码器释放、未持续增长的内存和正确剧情位置。
6. 用 Instruments 的 Time Profiler、Allocations、Leaks 和 Game Performance/Animation Hitches 保存原始 trace；工具内“运行诊断”仅提供辅助观察，不能替代 trace。
7. 低电量、热状态、内存压力和缺失素材下验证静态降级，保留原 App 视频墙/拖拽/搜索/斗地主手动回归。
