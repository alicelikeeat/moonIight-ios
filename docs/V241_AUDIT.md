# V2.4.1 实际基线与验收记录

## 基线核查
基线为 feature/treasure-map-v2-3（4775d0d）。本地、远端 main / cursor / feature 分支均未找到 V2.4 斗地主实现，因此本次新增三人单机基础，而非声称保留不存在的规则引擎。

- `MoonTreasureMapView.swift`：自由散落物理场景、视频墙与第三模式入口；场景保留，非自由模式暂停物理/预览。
- `TreasureVideoSelectionModel.swift`、`TreasurePlaybackCoordinator.swift`、`TreasureVideoWallView.swift`：原视频墙，10 项选择与独立并发策略保持。
- `MediaServices.swift`：现有导入媒体、稳定媒体 ID、库与播放队列。
- `LandlordRules.swift`：新增纯 Swift 54 牌身份、叫分、判型、压牌、提示、两家 AI、春天与零和虚拟积分。
- `LandlordGameStore.swift`：对局保存/恢复、选牌顺序、可取消 AI 任务，最近三局积分。
- `CardMediaPolicy.swift`：稳定循环映射、可见性/遮挡面积、优先级、两路上限、LRU、快照。
- `CardMediaCoordinator.swift`：按素材共享 AVPlayerItemVideoOutput，后台 actor 生成最大 320 像素预览，活动素材帧更新不驱动整张牌桌。
- `LandlordGameView.swift`：牌桌、中央最近三手、静态历史、原生单层玻璃、聚焦主动声音。

## 产品与资源策略
本地三人叫分制，0/1/2/3 分，三家不叫重发；无癞子、抢地主、联网、真实货币。顺子/连对/飞机主体不含 2 和王；飞机单翅允许对子拆作两张单翅，不允许主体含第四张作为翅膀；双翅必须不同点数的对子。四带二允许一对作为两张单牌，四带两对需要不同点数。

牌 ID 不因媒体样式/素材选择而改变。映射以局 UUID、素材选择顺序稳定计算，缺失素材不解码。选牌数组保留点击顺序，出牌后同一 ID 进入中央，不能再次操作为手牌。中央只渲染最近三手，更早静态记录不创建视频视图，单局最多 54 组，新局清空。

预算 0–2，默认 2；优先级为聚焦、最上手中央、我的手牌、其他可见部分；遮挡面积为多个矩形覆盖的并集。完全遮挡零槽位。相同素材只占一槽且加入同一时间轴；素材重新取得槽位从最近保存秒数恢复。每张牌保存媒体 ID、时间戳、最近帧引用与可见性。帧引用共用素材最近帧，LRU 淘汰后回退封面/经典文字。

缓存最多 24 项、12 MiB；内存警告降到 6 项、2 MiB，预览预算为 0，手动重启才恢复。高温/低电量或慢帧降到一路，严重高温静态。仅有槽位时运行 12 Hz 输出采样，不为 54 张牌创建计时器或播放器。图片封面后台串行缩略图解码；网络源限制 8 MiB。退出、切经典、新局取消任务/通知/输出/播放器与缓存。后台保存时间戳并释放，前台按可见性静音恢复。中断停止，焦点声音需主动重开。

## 风险与验证边界
当前环境只有 Linux 与 GitHub macOS 模拟器，无真实 iPhone、无 Instruments 设备会话。Allocations、Leaks、Time Profiler、Core Animation、真实内存峰值/持续值/FPS **尚未验证**。不开放未经实测的 3–4 路，不承诺数值性能或零泄漏。SwiftUI 布局、共享视频帧、长局与频繁切换仍需真机验收。

GitHub 验证记录将在实际构建完成后追加；新增代码目前不应视作已经编译通过。
